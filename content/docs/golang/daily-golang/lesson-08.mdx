# Go 指针与值语义：分清复制、修改与共享

上一课用 `Student` 结构体和方法组织了学员信息，也看到了指针接收者可以修改原对象。今天不再重复定义方法，而是回答背后的问题：**函数拿到的是哪一份数据？复制一个变量，是否就能得到完全独立的副本？**

前置知识是第 7 课的结构体与方法；示例继续使用“小李”和分数。今天只讨论指针基础、传参选择与避免意外共享，不展开接口、并发或内存优化。

## 学习目标

- 看懂 `*Student`、`&student` 和 `*p` 的含义，区分指针与它指向的值。
- 理解 Go 的赋值和函数传参都会复制值，包括指针值本身。
- 根据“返回新结果”还是“修改已有对象”选择传值或传指针。
- 识别指针别名、`nil` 和结构体中切片字段带来的共享问题。

## 核心概念

### 1. 指针保存地址，不是另一个完整的对象

把变量想象成一个盒子，指针就像写着盒子位置的便签。

- `p := &student`：`&` 取出 `student` 的地址，`p` 的类型是 `*Student`。
- `*Student`：出现在类型位置，表示“指向 `Student` 的指针类型”。
- `*p`：出现在表达式位置，表示访问指针指向的值，也叫解引用。
- `(*p).Score` 可以简写为 `p.Score`，但只有指针有效时才能访问字段。

**类型里的 `*` 和表达式里的 `*` 扮演不同角色。** 不需要记住地址长什么样，也不需要做地址运算；普通 Go 指针不支持像整数那样直接加减。

### 2. Go 始终按值传递，传指针也不例外

调用 `func change(s Student)` 时，函数得到结构体值的副本。本课 `Student` 只有字符串和整数，修改副本的 `Score` 不会改变原结构体。

调用 `func change(s *Student)` 时，函数得到的是**指针值的副本**。复制后的指针仍指向同一个对象，因此 `s.Score = 80` 会修改那个对象。

这里要分清两种动作：

- `s.Score = 80`：沿着地址修改对象。
- `s = &Student{Score: 80}`：只让函数自己的指针变量指向另一个对象，不会重新绑定调用者的指针变量。

所以不要把传指针叫成“Go 改为按引用传递”。规则始终是复制值，区别只是复制的值是否包含指向共享数据的地址。

### 3. `nil`：指针还没有指向对象

`var p *Student` 声明了一个指针变量，零值是 `nil`。它不会自动创建 `Student`，直接访问 `p.Score` 或 `*p` 会触发运行时 panic。

创建对象可以写 `student := Student{}` 后再取 `&student`，也可以写 `p := &Student{}`。前者有一个零值结构体，后者得到指向零值结构体的指针。

函数是否允许 `nil`，应有明确约定。本课的加分函数允许它，并返回 `false` 表示未修改；不要把忽略 `nil` 当作所有函数的通用做法。

### 4. 什么时候传值，什么时候传指针

| 目的 | 入门阶段的选择 | 调用者的预期 |
| --- | --- | --- |
| 读取较小结构体，计算结果 | 传值 | 不主动修改原对象 |
| 生成修改后的版本 | 传值并返回新值 | 调用者决定是否接收新版本 |
| 明确修改已有对象 | 传指针 | 允许函数改变该对象 |
| 表示“没有对象” | 可以使用指针和 `nil` | 调用前约定空值如何处理 |

不要因为“指针看起来更快”就到处加 `*`。它也会增加共享和理解成本；性能判断需要测量，不能只看类型大小猜结论。

上一课“只读可以传值、修改使用指针”的判断适合小结构体入门，但不是强制规则。只读函数也可以接收指针，而且传值不保证所有字段的底层数据都独立。

### 5. 避免不必要的指针共享

`alias := &student` 没有复制一个学员，只是多了一个访问原学员的入口。通过 `alias` 改分数，`student` 也会变化。如果只想试算，就复制值并返回结果，而不是先取地址再改。

还要联系第 5、6 课的知识：**结构体复制不是自动深拷贝。** 如果结构体有切片、map 或指针字段，复制后仍可能共享底层数据。例如下列片段放在函数内运行：

```go
original := struct{ Scores []int }{Scores: []int{58, 90}}
copyOf := original
copyOf.Scores[0] = 60
// original.Scores[0] 现在也是 60，因为两个切片共享底层数组。
```

对于这里的 `[]int`，要独立修改，可以先 `make` 一个新切片，再用 `copy` 复制元素；对于 map 需要逐项复制。若元素本身仍含指针等共享数据，还需继续判断，不能把一次复制当作万能的深拷贝。

## 代码示例

在一个新的空目录执行：

```bash
mkdir lesson08
cd lesson08
go mod init lesson08
```

把下面的完整程序保存为 `main.go`，再执行 `go run .`。所有函数都属于 `package main`，不依赖第三方包。

```go
package main

import "fmt"

type Student struct {
    Name  string
    Score int
}

// 返回修改后的副本，由调用者决定是否使用。
func withBonus(s Student, delta int) Student {
    s.Score += delta
    return s
}

// 约定：nil 表示没有学员，返回 false，不进行修改。
func addBonus(s *Student, delta int) bool {
    if s == nil {
        return false
    }
    s.Score += delta
    return true
}

// 只重新赋值函数自己的指针副本，不会替换调用者的指针。
func rebind(s *Student) {
    s = &Student{Name: "小王", Score: 100}
    fmt.Println("函数内重新指向:", s.Name, s.Score)
}

func main() {
    student := Student{Name: "小李", Score: 58}
    candidate := withBonus(student, 5)
    fmt.Println("传值后原分数:", student.Score)
    fmt.Println("返回的副本分数:", candidate.Score)

    p := &student
    fmt.Println("指针读取:", (*p).Score, p.Score)
    changed := addBonus(p, 5)
    fmt.Println("传指针后:", changed, student.Score)

    alias := p
    alias.Score = 70
    fmt.Println("共享指针修改后:", student.Score)

    rebind(p)
    fmt.Println("调用后仍指向:", p.Name, p.Score)

    var missing *Student
    fmt.Println("零值指针是 nil:", missing == nil)
    fmt.Println("空指针加分成功:", addBonus(missing, 5))
}
```

预期输出：

```text
传值后原分数: 58
返回的副本分数: 63
指针读取: 58 58
传指针后: true 63
共享指针修改后: 70
函数内重新指向: 小王 100
调用后仍指向: 小李 70
零值指针是 nil: true
空指针加分成功: false
```

按顺序观察：`withBonus` 产生新值而不改变原分数；`addBonus` 沿着复制的指针修改原对象；`alias` 与 `p` 指向同一学员；`rebind` 只改变局部指针变量；最后的 `nil` 检查避免了无效解引用。

## 练习

1. 在调用 `withBonus` 后写 `student = candidate`，先预测后续输出，再运行验证。说明这与函数直接修改原对象有什么区别。
2. 将 `alias.Score = 70` 改为 `independent := student` 和 `independent.Score = 70`，同时打印两者分数，解释为什么这次没有联动。
3. 为 `Student` 写一个只读函数 `passed(s Student) bool`，判断是否及格。解释为什么这里无需为了读取一个整数而传指针。
4. 将 `addBonus` 的 `nil` 分支改为打印“没有学员”，保留 `false` 返回值，验证调用者如何区分成功与未修改。
5. 运行核心概念中的切片共享片段，再通过 `make` 与 `copy` 让副本拥有独立的 `[]int`，验证修改副本后原分数不变。

自查标准：能够准确说出“复制了什么值、两个变量是否仍指向同一数据”，比背诵“指针能修改原值”更重要。

## 小结

今天建立的统一规则是：**Go 赋值与传参都复制值；复制指针会保留它指向对象的关系，复制结构体也不会自动深拷贝共享字段。** `&` 用来取地址，表达式中的 `*` 用来解引用，未初始化的指针是 `nil`。需要修改原对象时明确传指针，只想计算新版本时优先返回新值，并警惕不必要的别名共享。下一课将学习接口与多态，在理解值和指针的基础上认识不同类型如何表达相同的行为。
